# ADR-0053 — Plugin pin bump `4354903` → `3432b52` (Layer-A: cloud/EO sources become enforced detector rules)

- **Status:** Accepted
- **Date:** 2026-06-15
- **Deciders:** drumfiend21 (architect; 2026-06-15 directive to keep GCTP on the latest CTP `main`) + Claude (cloud session). Cross-corroborated by the CTP-side session (independent git verification: 71-commit `bba77df..3432b52` span additive; target suite 4253/0).
- **Trigger:** Immediately after ADR-0052 bumped the pin to `4354903`, CTP `main` advanced one commit to `3432b52` (CL-475, §28.15) which **activates** the cloud + governance source corpora as enforced detector rules ("Layer-A"). At `4354903` those seven namespaces were guidance-only (0 rubric rules) and ADR-0052 allow-listed them in the A3 citation guard; this bump turns them into rule-bearing namespaces, so the allow-list is reverted.

- **Process:** §15-gated pin bump (a `contract_surface_files` hash changed); lockfile updated by hand under this ADR.

## Context

ADR-0052 adopted CTP `4354903`, where `aws`/`azure`/`gcp`/`hashicorp`/`linux-foundation`/`security-governance`/`us-government` appeared in `namespaces_seen` but aggregated to **0 rubric rules** (architecture-guidance corpora feeding `/architect`, not detectors). To keep `audit-source-citations.sh` A3 green, ADR-0052 allow-listed those seven as legitimately rule-empty.

CTP CL-475 (§28.15, "Layer-A") then promoted those sources into **grounded, enforced detector rules**. GCTP should adopt it so the cloud/governance standards are actually enforced, not merely mirrored.

## Decision

Bump the pin `4354903` → `3432b52`:

- **Lockfile:** update `pinned_commit` / `pinned_at` / `pinned_message` and re-hash the one changed contract file (`architecture-v1.9.md`). `CLAUDE.md` + the 3 skill hashes are unchanged.
- **Revert the ADR-0052 A3 allow-list** for the seven cloud/governance namespaces. They now carry 2 detector rules each (aws, azure, gcp, hashicorp, linux-foundation, security-governance, us-government — 14 rules total, each with provenance), so `audit-source-citations.sh` A3 again *guards* them (a future silent drop is caught). Only `_community` remains allow-empty.
- **Refresh counts** in `README.md` (28 → 42 rubric rules; 8 → 15 rule-bearing namespaces).

## What changes for GCTP (honest scope)

- **Gained:** 14 enforced cloud/governance detector rules across `aws`/`azure`/`gcp`/`hashicorp`/`linux-foundation`/`security-governance`/`us-government` — GCTP now enforces cloud-architecture **and** governance/EO standards at the same write-time bar as the existing 8 namespaces. This includes 2 `security-governance` rules grounded in the EO authorities (CISA SSDF/KEV, NIST AI RMF, SLSA).
- **On the `eo`-namespace guard (correcting an earlier framing).** GCTP's `audit-eo-governance.sh` keys on a *literal* `source_namespace: eo`, which CTP does not emit **by design** — CTP enforces EO under the `security-governance` namespace (plus CTP-side gates: the H-14 vuln find-and-fix gate, the `eo-security.yaml` convention ruleset, and the §2.33 citation-conformance auditor). So that one guard still reports "vacuous." **This is a measurement property of that guard's namespace key, NOT an absence of EO enforcement** — the EO/governance rules ARE enforced in GCTP now, via the `security-governance` detector rules through the normal `applicable_rules` → `rules_verified` machinery. Earlier notes that read "vacuous ⇒ EO unenforced" were a misread.
- **Open option (deferred, operator call):** GCTP could repoint `audit-eo-governance.sh`'s `EO_NAMESPACES` from `eo` to `security-governance` to also apply the non-exemptibility + two-phase-attestation machinery (ADR-0045/0046) to those rules. That is a policy tightening (every app-code ticket would then have to carry the `security-governance` rules and every green response an `eo_design_conformance`), so it is left as a separate decision rather than bundled into this pin bump.

## Alternatives considered

- **Stay at `4354903` (guidance-only).** REJECTED — leaves the cloud/governance standards mirrored but unenforced; the operator wants the latest, and Layer-A is the point of the bump.
- **Keep the A3 allow-list for the seven namespaces.** REJECTED — they are now rule-bearing; keeping them allow-empty would silently tolerate a future total rule drop. Reverting restores the guard.

## Consequences

### Positive
- Cloud-architecture + governance standards are now *enforced*, not just present.
- A3 guards all rule-bearing namespaces again; the allow-list shrinks back to `_community`.

### Negative
- The enforced bar is strictly higher (more P0/P1 rules). Intended.

### Neutral
- No `claude-tdd-pro` path edited (prime directive); consumer-side lockfile change only.
- `schema_version` + the 3 executed skill hashes unchanged; D-6 honored (`docs/founder-directives.md` untouched).
