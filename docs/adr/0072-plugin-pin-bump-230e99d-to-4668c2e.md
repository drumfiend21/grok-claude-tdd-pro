## §4 decision — move tool-based enforcement to pre-write (operator-directed)

CTP's §4 open question (the design of §28.60 govern-before-write / §28.68 both-paths pre-write): tool-based enforcement (~80 routed FOSS tools) is currently **post-write/audit** on the plugin side; native enforcement already runs pre-write. **Operator decision (2026-06-30): MOVE tool-based enforcement to pre-write too** — wire `composite-dispatch` into the harness pre-write governor so routed tools also deny before write. This is **recorded here** and **implemented in CL-B..N** (the PreToolUse `enforce-standards-pre-write.sh` wiring), not in this integration-only bump. Tradeoff accepted: added per-write latency (tool spawn) for maximal enforcement.

At `4668c2e`, CTP wired that bundle (§28.42), so `composite-dispatch` now produces a finding on architectural `.md` — but the gate's deviation-clearing (`## Deviation — <rule-id> on <ticket-id>`) does not yet map the composite-engine rule-ID surface, so a deviated design is not cleared and the gate blocks (exit 1) where it should proceed (0). **This is wiring-adaptation, not a pin-bump defect** — the gate must be taught the composite-dispatch rule-ID format. Deferred to the design-phase-md wiring CL (CL-B..N). `audit-design-phase-md` is a **dispatch-time WARN gate** (session-start WARN per ADR-0001; not a pre-commit hard gate), so this does not block commits.
