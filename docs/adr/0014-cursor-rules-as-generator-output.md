# ADR-0014 — `.cursor/rules/` as generator output (TICKET-013)

- **Status:** Accepted
- **Date:** 2026-05-26
- **Deciders:** drumfiend21 (architect, "Proceed" instruction on the reconciled TICKETS-011-014 plan) + Claude (cloud session, implementer)
- **Supersedes:** none
- **Extends:** ADR-0012 (AGENTS.md cross-tool surface — this ADR builds the Cursor always-loaded-rule layer that AGENTS.md §7 forward-references); ADR-0015 (Cursor as host IDE — this ADR materializes the session-start mechanism documented in `docs/cursor-integration.md §7`); ADR-0009 (audit-doc-drift mechanism — this ADR adds F-5 to it); composes on `docs/founder-directives.md §3` (D-rule headers, sourced for d-rules.mdc) and `docs/quality-gate.md` (source-of-truth for quality-gate.mdc)

## Context

Cursor's always-loaded rule mechanism (`.cursor/rules/*.mdc` with `alwaysApply: true` in the front-matter) is the functional equivalent of Claude Code's `.claude/hooks/session-start.sh` push-hook. AGENTS.md §7 (TICKET-011) and `docs/cursor-integration.md §7` (TICKET-012) both forward-reference this surface; TICKET-013 ships it.

Four `.mdc` files materialize the Cursor-side surface:

- `.cursor/rules/agent-context.mdc` (always-loaded) — session-start ritual + skill paths + authority pointers.
- `.cursor/rules/harness-overview.mdc` (agent-loaded) — two-tier outer/inner loop summary.
- `.cursor/rules/quality-gate.mdc` (agent-loaded) — sub-gates surfaced from `docs/quality-gate.md`.
- `.cursor/rules/d-rules.mdc` (agent-loaded) — D-1..D-13 headers parsed from `docs/founder-directives.md §3`.

Three design questions had to be resolved:

1. **Hand-edit policy.** Are these files generator output (DO NOT EDIT) or hand-maintainable surfaces (the operator may tune)?
2. **Generator coupling.** How does the generator wire into the session lifecycle so fresh clones get the files, and so the files stay synchronized with their sources-of-truth?
3. **Drift detection.** How does the audit catch the failure mode where the files drift from the generator output (hand-edit, or a source-of-truth change without regeneration)?

## Decision

### 1. Generator-output-only; hand-edits forbidden

Every `.cursor/rules/*.mdc` file carries a `# Generated by scripts/export-cursor-rules.sh — DO NOT EDIT` header. The convention is binding: hand-edits are forbidden because (a) the next `sync-plugin.sh --ensure` will clobber them silently, and (b) the audit's F-5 pattern catches drift at pre-commit (so silent clobber is replaced by visible audit failure).

The generator is a single bash script (`scripts/export-cursor-rules.sh`) with one function per output file. The generator's content is the source-of-truth for `.cursor/rules/agent-context.mdc`, `.cursor/rules/harness-overview.mdc`, and the framing of `.cursor/rules/quality-gate.mdc` (the sub-gate names + their require/recommend status are also surfaced from the source via the generator's literal text). The `.cursor/rules/d-rules.mdc` file has a dynamic component: the D-rule headers are parsed from `docs/founder-directives.md §3` via awk, so changes to §3 are reflected automatically on next regeneration.

To change `.cursor/rules/agent-context.mdc` content: edit the generator. To change a D-rule header: edit `docs/founder-directives.md §3` (which itself requires an ADR per D-6) and regenerate. To change a quality-gate sub-gate definition: edit `docs/quality-gate.md` AND update the generator's mirror text in the same CL (the generator's text is currently a hand-maintained mirror, not a parse — see "Negative" below).

### 2. Wire into `scripts/sync-plugin.sh --ensure`

The generator runs as an additive step at the end of `sync-plugin.sh --ensure`: after the plugin cache is materialized and the symlinks are validated, but before `exit 0`. The step is defensive (only runs if `scripts/export-cursor-rules.sh` exists and is executable; non-zero exit is logged as a warning rather than failing `--ensure`). This wiring means:

- A fresh `git clone` followed by the Claude Code SessionStart hook (or the manual `./scripts/sync-plugin.sh --ensure` per AGENTS.md §7) materializes `.cursor/rules/*.mdc` automatically — Cursor's chat agent has the always-loaded rule on first session open.
- A developer who runs `./scripts/sync-plugin.sh --ensure` after editing the generator or one of its sources sees the regenerated files in the same invocation; no separate command to remember.
- The generator is idempotent: `--check` mode (writes to temp, diffs against on-disk, exits 1 on drift) is the canonical "did the operator edit by hand?" probe.

The `.cursor/rules/*.mdc` files are committed to git (the `.gitignore` does NOT exclude them). Rationale: a fresh clone before the first `--ensure` should still have the files available so Cursor's chat agent on first open has the always-loaded rule, before the SessionStart hook has run. The generator-output-only invariant is enforced post-commit by F-5, not by gitignore.

### 3. F-5 pattern: re-run generator in `--check` mode, diff against on-disk

The audit's F-5 pattern calls `scripts/export-cursor-rules.sh --check --quiet` and emits a finding for any file that has DRIFTED or is MISSING from on-disk. Implementation: `--check` mode writes to a temp directory (cleaned via trap), uses `diff -q` against `.cursor/rules/`, and exits 0 (no drift) or 1 (drift). The audit captures the human-readable output and turns each DRIFT/MISSING line into a `[doc-drift] F-5 ...` finding.

This is the audit's first multi-file generator-output pattern — F-1/F-2/F-3 catch stale-string patterns in single files, F-4 catches help/impl mismatches in one script. F-5 generalizes to "generator output vs source-of-truth parity" and could be reused by future generators (e.g., a TICKET-015 MCP-tool manifest generator) without script changes.

## Alternatives considered

- **Hand-maintainable `.cursor/rules/*.mdc` files (no generator).** Rejected per D-12 (production-grade trust): five+ files maintained by hand across multiple operators will drift. The generator + F-5 audit pattern is the structural enforcement.
- **YAML front-matter only; no `# Generated by` body header.** Rejected. Cursor's `.mdc` front-matter is parsed by Cursor; the operator-visible content starts after the `---`. Putting the "DO NOT EDIT" warning only in front-matter risks the operator scrolling past it. Body-comment placement is operator-visible.
- **Run the generator from a git pre-commit hook instead of `sync-plugin.sh --ensure`.** Rejected per D-8 (delete the part) — adding a git hook is a new mechanism class for this repo; reusing the existing session-start invocation path is simpler. The audit's F-5 pattern at pre-commit time catches the case where the generator wasn't re-run after a source change.
- **Generate `quality-gate.mdc` by parsing `docs/quality-gate.md` headers + bullet structure** (analogous to `d-rules.mdc`'s parse of §3 headers). Rejected at v1: `docs/quality-gate.md`'s structure is denser than `§3`'s "one header per rule" — parsing risks fragility. The current hand-maintained mirror inside the generator is acknowledged in "Negative" below; a future ADR can promote to parse if the quality-gate doc's structure is stabilized for machine parsing.
- **Gitignore `.cursor/rules/*.mdc` (force fresh generation on every clone).** Rejected. A fresh clone before the SessionStart hook runs would have no always-loaded rule; Cursor's chat agent on the very first interaction would miss the session-start ritual. Committing the files ensures the always-loaded rule is live from the first session.
- **Drop `d-rules.mdc` — Cursor agent reads `docs/founder-directives.md §3` directly.** Rejected. The D-rule headers are a high-value 13-line catalog; surfacing them in a small always-available file is cheaper than asking the agent to grep §3 every session. The §3 body is the canonical source (per D-6); `d-rules.mdc` is the catalog, not the canonical text.
- **Wire generator into git pre-push hook.** Rejected per D-8 — duplicates the F-5 pre-commit audit's role.

## Consequences

### Positive

- **Cursor's chat agent now has a session-start ritual on first session open.** `.cursor/rules/agent-context.mdc` always-loads with the same instructions a Claude Code agent gets from `.claude/hooks/session-start.sh`. The session-start asymmetry between Cursor and Claude Code is closed at the operator-visible level (the mechanism difference remains and is documented in `docs/cursor-integration.md §7`).
- **TICKETS 011-012 forward-references are now materialized.** `AGENTS.md §7` and `docs/cursor-integration.md §7` reference `.cursor/rules/agent-context.mdc`; those references are now live.
- **F-5 audit pattern generalizes to future generator-output families.** A future TICKET-017 (MCP-tool manifest), TICKET-NNN (any other generator) can hook into the same F-5 mechanism without modifying `audit-doc-drift.sh` beyond adding the script's path to a small enumeration.
- **D-1 reverse attribution honored per ADR-0013.** Each `.cursor/rules/*.mdc` cites its Grok / Claude analog (or rationale for "no analog — harness-native").
- **Generator is idempotent.** Re-running produces zero diff; the contract is exit-0 verifiable via `--check` mode.
- **`.cursor/rules/d-rules.mdc` auto-tracks §3.** When a future ADR adds D-14, the next `--ensure` (or manual generator invocation) picks up the new header without manual `d-rules.mdc` edits.

### Negative

- **`.cursor/rules/quality-gate.mdc` content is a hand-maintained mirror inside the generator** (not a parse of `docs/quality-gate.md`). If `docs/quality-gate.md` changes a sub-gate's REQUIRED/RECOMMENDED status or default value, the generator's text must be updated in the same CL or the mirror drifts from the source. Mitigation: the Q-DOC-DRIFT checklist item (`docs/founder-directives.md §4`) requires updating downstream operator-facing docs; the generator text is one such doc. Promotion to parse-based generation is a future-ADR candidate when the quality-gate.md structure is stable enough to parse reliably.
- **`sync-plugin.sh --ensure` is now coupled to `scripts/export-cursor-rules.sh`.** If the generator script is deleted or moved, `--ensure` will silently skip the generation step (logged as a warning, not a hard failure). Mitigation: F-5 at pre-commit catches the resulting drift (on-disk `.cursor/rules/*.mdc` becomes stale relative to a future regeneration); the generator missing entirely would surface as "F-5: missing on disk: ..." on the first audit after regeneration is attempted.
- **The 4-file output set is fixed at v1.** Adding a 5th `.cursor/rules/*.mdc` file requires editing the generator's `OUTPUTS` list and adding a `gen_*` function. Mitigation: this is a deliberate operating constraint; new always-loaded rules should be considered carefully per D-13 (context-as-fundamental-constraint).
- **The `# Generated by` comment header lives in the markdown body, not in YAML front-matter.** Some Cursor model context may display the body comment to the chat agent as if it were rule content. Mitigation: comments are leading `#` lines that the agent will treat as markdown headings or comments; agent confusion risk is low.

### Neutral

- **D-rule count unchanged.**
- **TIER-0 corpus untouched.**
- **§1 provenance, §3 D-rule bodies, §4 D-checklist items untouched.** (D-1 reverse item from ADR-0013 already present; this ADR does not modify §4.)
- **`schema_version` of the handoff contract unchanged.**
- **`scripts/sync-plugin.sh --help` text unchanged** (no new `--*` flag added; F-4 still passes).
- **AGENTS.md untouched** (the forward references in TICKET-011 are now materialized, but AGENTS.md doesn't need re-pointing).

## Verification (executed before commit)

- `./scripts/export-cursor-rules.sh` exits 0; writes 4 files.
- `./scripts/export-cursor-rules.sh --check` exits 0 immediately after generation (idempotent — second invocation produces zero diff).
- All 4 output files carry `^# Generated by scripts/export-cursor-rules.sh — DO NOT EDIT$` header.
- `./scripts/audit-doc-drift.sh` exits 0.
- F-5 catches hand-edit: append a `# HAND EDIT` line to any `.cursor/rules/*.mdc`; `./scripts/audit-doc-drift.sh` emits an `F-5 (cursor-rules drift):` finding and exits 1; `./scripts/export-cursor-rules.sh` regenerates; audit returns to exit 0.
- `./scripts/smoke-e2e.sh` exits 0 (toy at Red baseline; this CL touched no executable beyond the new generator + audit hook).
- `./scripts/sync-plugin.sh --help` output unchanged (F-4 still passes).
- `./scripts/sync-plugin.sh --ensure` runs the generator additive step and reports `cursor    : .cursor/rules/*.mdc generated`.
- `bash -n` clean on all three modified/new scripts.

## Out of scope (deferred)

- **Parse `.cursor/rules/quality-gate.mdc` from `docs/quality-gate.md`.** Deferred until the source's structure is stable enough for safe parsing.
- **Per-Cursor-model rule tuning.** Deferred per D-8 — don't optimize before the un-tuned version is in use.
- **`.cursor/rules/*.mdc` change-detection at session-start in Cursor.** Cursor's own SessionStart-equivalent UX (does it warn the operator when an always-loaded rule changed?) is Cursor's concern, not ours.
- **MCP-tool manifest generator.** Deferred to TICKET-017 / ADR-0017 (would reuse the F-5 audit pattern).
- **Hash-based source-tracking inside `.cursor/rules/*.mdc`** (e.g., embed `# source-hash: <sha256>` and have F-5 just compare hashes rather than regenerate). Considered; rejected at v1 for added complexity vs. the simpler "regenerate and diff" approach. Promote if generator runtime becomes a bottleneck.
